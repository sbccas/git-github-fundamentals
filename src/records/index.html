⭐ The most-starred repositories

A star is GitHub’s bookmark: one click says “I like this” and saves the repository to your list. These are GitHub’s own top 10 out of every public repository.

Top 5 compared

What makes a repository popular?

📚 Useful to beginners. Lists, books, roadmaps and interview guides help millions of learners, so most of the top 10 are learning resources, not apps.
📄 A clear README. People star what they understand in 30 seconds: what it is, why it matters and how to start.
🔁 Shared widely. Links on social media, blogs and newsletters bring waves of new visitors and stars.
🛠 Kept alive. Regular updates, answered issues and welcomed pull requests keep people coming back.
⏳ Time. Older repositories have had years to collect stars; a new one with a huge count has grown unusually fast.

⚠️ Stars measure attention, not quality

Stars can be bought or faked. A 2024 study found about six million suspected fake stars on GitHub (He et al., ICSE 2026). Some repositories in this list are less than a year old. Before you trust a project, look at its code, recent commits, issues and contributors too.

🍴 The most-forked repositories

A fork is your own copy of someone else’s repository on GitHub. You can change your fork freely and later offer changes back with a pull request.

Why these? Many top forks are course assignments: an online course tells every learner to fork its repository, so forks grow faster than stars. That is why some repositories here have far more forks than stars.

🔀 The most pull requests

A pull request (PR) asks a project to take your changes. GitHub has no official “most pull requests” ranking, so we counted the busiest public repositories ourselves.

Opened, merged or closed?

Every pull request is open (waiting for review), merged (accepted into the project) or closed without merging (declined, replaced or abandoned). The bars show the split for the six largest.

Projects such as odoo/odoo merge with their own bot, which adds the commits itself and then closes the pull request. GitHub then shows it as “closed”, even though the change was accepted.

Repositories with the most conversations

GitHub does not publish a comment total for a whole repository, and its free API stops listing after 30,000 pages. What we can count exactly is the number of conversations: issues and pull requests, each counted once.

Issues and pull requests with the most comments

Well-known conversations, with their comment and reaction counts. The two at the bottom are filled mostly by bots: in our check, many such threads showed exactly 2,500 comments and none showed more, which suggests GitHub stops counting there.

📜 The most commits

A commit is one saved snapshot. Repositories with the longest histories have been saving snapshots for decades, often from thousands of people.

💡 Why do some projects have so many commits?

  • Age: Linux has history back to 2005, when Git was created for it.
  • Size: browsers and compilers (Chromium, Firefox, LLVM, GCC) are millions of lines of code worked on every day.
  • Many small updates: package collections such as nixpkgs, Homebrew and winget get one commit for every new version of every app they list.
  • Mirrors: some repositories here are copies of a project that lives on its own server; GitHub only shows the history.

Sources and method

  • Snapshot: collected from the public GitHub REST API on the date shown with each section, without a token, and checked by hand. Faculty can refresh it with node scripts/github-records.mjs.
  • Live data: the “Check live numbers” button asks GitHub’s public search directly from your browser. Nothing is sent anywhere else and no account is needed. GitHub allows 10 searches a minute for each network, so in a computer lab where many press it at once, some will see the snapshot instead and can try again a minute later.
  • Counts change: stars, forks and pull requests grow every minute. Small differences from what you see on GitHub are normal.
  • Not a recommendation: repositories appear here because of their numbers. Being on this page does not mean we have checked or recommend their content.
